Ты проводишь автоматический код-ревью проекта Smart Store CRM в режиме read-only.
Твоя задача — строго следовать правилам из AGENTS.md и предоставить структурированный отчет на русском языке.

Инструкции для ревьюера:
1. Прочитай файл AGENTS.md и строго следуй всем разделам: «Development rules» и «Review rules».
2. Проверь статус репозитория (git status, git diff) и внимательно изучи все измененные, новые или незакоммиченные файлы.
3. Проверь проект на:
   - Ошибки логики, состояния React, хуков и эффектов;
   - Строгий TypeScript (любые `any` и `@ts-ignore` строго запрещены);
   - Соблюдение правил складского учёта (неотрицательные остатки и цены, корректные типы number, фиксация складских движений при изменениях, запрет повторного проведения, запрет дубликатов позиций);
   - Доступность модальных окон (фокус при открытии, ловушка фокуса/focus trap по Tab/Shift+Tab, закрытие по Escape, возврат фокуса при закрытии);
   - Корректный возврат фокуса при удалении/архивировании элементов: фокус должен возвращаться на видимую кнопку «Добавить товар» (не выбирая скрытую мобильными стилями кнопку);
   - Доступную навигацию с клавиатуры для выпадающих меню (ArrowUp, ArrowDown, Home, End, Escape с возвратом фокуса на кнопку вызова);
   - Маршрутизацию, формы, валидацию данных;
   - Корректность классов стилей (SCSS Modules), отсутствие ссылок на несуществующие классы;
   - Работоспособность Dashboard и других существующих страниц.
4. Ни в коем случае не изменяй файлы проекта! Твой режим — строго read-only.
5. Итоговый отчет должен быть написан на русском языке в формате Markdown со следующей структурой:

# Отчет Codex Code Review

## Общее резюме
Краткое описание проверенных файлов и общий вывод.

## Список замечаний
Сгруппируй замечания по приоритетам:
- **P0**: Блокирующие критические ошибки (падения приложения, потеря данных, невозможность сборки, нарушение правил складского учёта).
- **P1**: Ошибки высокой важности (нарушения бизнес-логики, недоступность критического UI, некорректная работа с фокусом или состоянием, утечки памяти).
- **P2**: Замечания средней важности (недочёты валидации, проблемы управления фокусом/a11y в краевых случаях, несоответствие требованиям ТЗ).
- **P3**: Низкий приоритет и рекомендации (микрооптимизации, кодстайл, оформление).

Для каждого найденного замечания укажи:
- Файл и номер строки (`файл:строка`);
- Описание проблемы;
- Рекомендацию по исправлению.

Если замечаний определенного уровня нет, укажи «Замечаний нет».

## Вердикт
Если критических и блокирующих ошибок нет (нет замечаний P0, P1, P2), явно укажи:
«Этап можно принять».
