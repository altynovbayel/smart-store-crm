# Smart Store CRM

## Project stack

- React
- Vite
- TypeScript strict
- React Router
- SCSS Modules
- lucide-react
- Supabase будет подключён позже

## Development rules

- Не использовать any.
- Не использовать @ts-ignore.
- Не отключать проверки TypeScript или линтера.
- Не добавлять новые production-зависимости без явного разрешения.
- Не менять существующий дизайн и работающую функциональность без необходимости.
- Сохранять компонентную архитектуру.
- Не создавать слишком большие компоненты.
- Общие типы хранить в src/types.
- Бизнес-логику и вычисления выносить из JSX.
- Денежные значения и складские остатки должны использовать number.
- Не допускать отрицательных цен и остатков.
- Не дублировать товары в одном документе прихода или продажи.
- Проведённые складские документы нельзя проводить повторно.
- Все изменения склада должны создавать складское движение.

## Review rules

Когда пользователь просит проверить работу:

- сначала изучи git diff и все незакоммиченные файлы;
- ищи ошибки логики, TypeScript, состояния React и складского учёта;
- проверяй маршруты, формы и валидацию;
- проверяй доступность модальных окон;
- проверяй, что новые изменения не ломают Dashboard и другие готовые страницы;
- запускай npm run build;
- запускай npm run lint;
- сообщай сначала о критических ошибках, затем о менее важных;
- указывай конкретные файлы и строки;
- не изменяй файлы во время review без прямого разрешения пользователя;
- если ошибок нет, явно сообщай, что этап можно принять.

## Implementation rules

Когда пользователь прямо просит исправить найденные проблемы:

- исправляй только подтверждённые проблемы;
- не переписывай несвязанные части проекта;
- после изменений запускай npm run build и npm run lint;
- показывай краткий список изменённых файлов.
